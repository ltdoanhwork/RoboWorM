PhyWorld-NR — what each metric actually reacts to

Every clip below is the analysis clip: re-created with the same prepare() the scorer used, so it is the same view crop, the same 5 fps sampling and the same 256×192 grid that produced the number. The conditioning frame is dropped, exactly as in scoring. Numbers come from table_dense_nr.gated(), i.e. the current gates.

The galleries show model predictions only; the reality check at the end puts each prediction next to its own real video. Each card also lists the other columns, so you can see that the metrics move independently — and a clip may legitimately appear in two galleries if it is weak on two of them.

Actor Activity px / source frame

How much the robot and the objects move, in pixels per source frame. This is NOT a score: more motion is not better, because the real video defines the right amount. It is reported so the other columns can be read next to it.

No poor/good here. There is no "good" value to show: the co-located real video defines how much the robot should move, so this column is descriptive. The verdict column is the paper's, not this page's. It reports membership of CEILING_FAILED in assets/scripts/table_dense_nr.py, which was decided by the pre-registered audit over the whole wave — not by the sample shown here. Counting per configuration (not per clip) is deliberate: pooled over clips, a metric can look like it prefers reality simply because the configurations that happen to have the most clips are the ones where it does.
How to read a failure. "Ceiling failed" does not mean the metric is useless — it means its absolute value may not rank models, because it is insensitive to the gap between real and generated video. Such a column is still valid for comparing a method against its own dense baseline, where that insensitivity cancels on both sides of the difference.
